# 通用规矩（可直接复制进某个项目的 AGENTS.md）

下面是**跟具体项目无关**的那部分。项目专属的（这个项目是什么、硬规矩、验收命令）自己补在前面。

---

## 文件卫生：删得掉、找得回

这个项目有版本控制。除了忽略清单里的大体积工具与中间数据，所有东西都在里面。

- **可以放心删**，删错了 `git checkout -- <路径>` 找回来。**不许再手写备份文件**
  （`xxx_backup`、`xxx_旧版`、`xxx_before_tune`、`副本` 这类）—— 要留旧版本就提交一次。
- **生成物不许直接改**：由构建脚本产出的文件（打包好的单文件、编译结果、自动生成的表）
  要改就改源文件再重新生成。
- **大体积的东西进忽略清单**：工具本体、导出的中间数据、数据库、截图、日志、安装包。
  这些留在磁盘上照常能用，只是不进版本控制。新增大文件之前先想想该不该忽略。
- **一次性脚本**（`dump_*`、`dbg*`、`diag_*`、临时截图）：用完就删；
  确实还要再用的放到 `工具/`，并在文件开头写一行"什么时候用过、怎么跑"。
- **改完一块就提交一次**，说明写清"做了什么、为什么"。提交历史就是进度记录，
  不需要再往文档里抄一份"已完成"。

## 文档放哪、怎么写

**一种信息一个位置，按寿命分开。** 混在一起一定"只增不减、重点被埋"。

一条东西不知道放哪时，**从上往下问，第一个"是"就定了**：

1. **换谁来都必须照做**吗？（硬规矩、验收命令、不许做什么）→ `AGENTS.md`
2. **做完就要划掉**吗？（现在到哪、下一步、卡在哪）→ `TODO.md`
3. 以上都不是 → `记录/`（踩过的坑、当时的数字、为什么否掉某个方案、写不出验收标准的想法）

第四类：**模块说明**（每个模块一份 `*_说明.md`）—— 按主题写、跟着模块走、只追加、不设上限。
它和记录的区别：**记录按时间，说明按主题**。

常见放错：「已完成」写进 `TODO.md`（应进记录）；历史写进 `AGENTS.md`（应只留"所以现在不许这么干"）；
规矩写成待办（规矩不能勾掉）；待办写成愿望（没有验收标准就进想法池）。

| 放哪 | 放什么 | 怎么读写 | 上限 |
|---|---|---|---|
| `AGENTS.md` | 硬规矩、验收命令、工作方式 | 人手动改 | 60 行 |
| `TODO.md` | 当前状态 + 还没做的事 | **每次整份重写** | 120 行 |
| `记录/YYYY-MM.md` | 干了什么、踩了什么坑、当时的数 | 追加，随便长 | 无 |
| 说明文档（如 `说明.md`） | 用了哪些外部数据、哪些还没对上 | 追加 | 无 |
| 系统临时目录 | 一次性交接纸条 | 用完就丢 | 一屏 |

- **`TODO.md` 只写"现在"，不写"历史"**，超过 120 行就先归档再写。做完了就删掉，往记录里写一行；
  测试数据带日期，重测后就地改；不留"已完成"清单，不用删除线记旧事。
- **每条待办要写得出"怎么算做完了"**（一条命令 / 一个数字 / 一张要对比的截图）。
  写不出来的不是待办，是想法，写进记录的"想法池"。
- **收尾三件事**：① `TODO.md` 删掉做完的、把剩下的改一遍；② 往 `记录/YYYY-MM.md` 追加几行；③ 提交。
- **什么时候做**（按事件，不按日历）：一块做完了 / 一次会话结束 / `TODO.md` 超过 120 行 /
  找某个文件或某条结论花了超过 10 分钟。

## 语言

平白简单的语言，不造术语，不主动简写。需求有歧义时先说清理解和备选方案，等确认再动手。

# 文件骨架

照抄改改就能用。`<...>` 是占位，删掉尖括号换内容。

---

## 1. `TODO.md`（不超过 120 行）

```markdown
# TODO —— 现在要做什么

> **规则：这个文件每次整份重写，不追加。超过 120 行就先归档再写。**
> 做完的东西、踩过的坑、当时的数字，写进 `记录/<年>-<月>.md`，不写这里。
> 写不出「怎么算做完了」的，也写进那份记录（想法池），不写这里。

## 现在唯一要做的

**<一句话说清这件事。>**

缺什么、卡在哪、别用什么（踩过的坑）——三五行说清。
哪个模块/函数/命令，直接写名字和路径。

验收：<一条命令，或一个数字，或一张要对比的截图。>

## 动手前先读

| 文件 | 看什么 |
|---|---|
| `<规矩文件>` | <硬规矩、验收命令> |
| `<上一份交接>` | <做到哪、改了什么、偏离与待拍板> |
| `<历史归档>` | <以前的全部记录，只在查证时翻> |

## 验收命令

| 命令 | 干什么 | 多久 |
|---|---|---|
| `<命令>` | <一句话> | <几秒> |

## 当前状态（<日期>，重测后要更新这段）

<三五句话：现在能跑什么、主干到哪一步、哪块是原版、哪块还是自己写的。>
<关键数字一行，带日期和来源。>

## 待办

### A. <主线>

1. **<做什么>** —— <现状一句话>。
   验收：<命令 / 数字 / 截图>。
2. ...

### B. 已知偏离 / 待拍板（**别当 bug 乱改**）

1. **<偏离点>** —— 为什么这样、什么时候能改回来。验收：<条件>。

## 想法池

写不出验收标准的，都放 `记录/<年>-<月>.md` 的「想法池」一节，不放这里。
```

## 2. `记录/YYYY-MM.md`（只追加，随便长）

```markdown
# <年> 年 <月> 记录

> 这份只追加、不删。没人会从头读它，**只在查证"当时为什么这么干"的时候翻**。
> 想知道现在要做什么，看项目根目录的 `TODO.md`。

## 想法池（暂时写不出「怎么算做完了」的）

- **<想法>**：<一句话背景，以及为什么现在不做>

## 大坑（都踩过，别重犯）

1. **<坑的名字>**：<症状 + 原因 + 怎么发现的>。
2. ...

## 时间线（一行一条，详情翻归档）

- **<月-日>** <干了什么>。
- ...

## <日期> <这次重构/交接做了什么>

- <一行一条>
```

## 3. `.gitignore` 起步模板

```gitignore
# 依赖 / 缓存
node_modules/
__pycache__/
*.pyc

# 大体积工具与中间数据（文件留在磁盘上，只是不进版本控制）
# <按项目补：数据库目录、导出目录、工具本体、安装包>
*.apk
*.zip

# 日志
*.log
*.tmp
```

> 注意：`.gitignore` **不支持行尾注释**。`work/xxx/   # 说明` 这样写会整条失效，
> 注释必须单独一行。

## 4. `AGENTS.md` 骨架（不超过 60 行）

```markdown
# 本项目的工作规矩
（这个项目是：<一句话>。）
> 现在做什么看 `TODO.md`；历史与坑看 `记录/`；<细则文件>看 `<路径>`。

## <硬规矩的名字>
<这个项目绝不许违反的事。每条一行，能判定、能验收。>

## 验证怎么算过
```bash
<验收命令，每条带一行注释>
```
<哪一条过了才算完成、哪一条只是参考。>

## <专项守则，如"每次改完必须过某个检查">
<硬性要求，三到五条。>

## 文件卫生：删得掉、找得回
<抄 `references/标准.md` 那一节>

## 文档放哪、怎么写
<抄 `references/标准.md` 那一节>

## 语言
平白简单的语言，不造术语，不主动简写。需求有歧义时先说清理解和备选方案，等确认再动手。
```
